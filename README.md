# Technical and Design Documentation: Project Rami

Below is the specification for the architecture, mechanics, and privacy-first design of the **Rami** single-player, client-only, local-first educational ecosystem.

---

## 1. Project Overview
**Rami** is a single-player, **100% client-only and local-first** educational platform aimed at children. There is no backend server, no accounts database, and no network telemetry. The main environment is an isometric 2D world ("The Wonder Tree") where users navigate using predefined avatars. The game uses an on-demand module loading architecture (dynamic ES module chunking) to support a rich library of minigames while keeping initial load fast, and stores all player profiles and progress strictly on the device.

---

## 2. Technology Stack
* **Architecture:** **Client-Only / Local-First** (zero servers, offline-ready).
* **Language & Build Tool:** **TypeScript + Vite** for strict static typing, fast HMR, and automatic code-splitting for minigames.
* **Game Engine:** **Phaser 3** (WebGL / Canvas) for isometric 2D rendering, tweens, physics, and multi-touch/keyboard input.
* **Target Platforms:**
  * **Web (Primary):** Automatically deployed as a static site to **GitHub Pages** via GitHub Actions (`.github/workflows/deploy.yml`).
  * **Android & iOS:** Packaged natively via **Capacitor** (`capacitor.config.ts`) from the same `dist/` web bundle.
* **Asset & Minigame Management:** Dynamic `import()` chunks via `MinigameLoader.ts`, loading minigame bundles on-demand when the player walks into a portal.
* **Environment Generation:** Data-driven JSON world schemas (`public/world.json`) and modular TypeScript scenes (`src/scenes/`), making it simple for AI agents and developers to generate or modify tree nodes, branches, and portals.

---

## 3. Local-First User Architecture and Privacy (COPPA Safe by Design)

Because Rami has **no server**, no personal data of the minor is ever collected or transmitted off-device.

### On-Device Guardian Dashboard (Parents/Teachers)
* **Local Profiles (`ProfileManager.ts`):** Allows creating multiple local child profiles on the same device, switching active players, setting an optional 4-digit on-device Guardian PIN gate, and reviewing local progress metrics across Solving, Creativity, and Logic minigames.

### Minor Profiles (Players)
* **Name Generation (`UserManager.ts`):** Explorer names are generated by combining a nature/mineral element with an animal (e.g., *Quartz Dinosaur*, *Basalt Raccoon*, *Agate Owl*).
* **Strict Avatars:** Photo uploads are not used. Users choose from predefined 2D illustrations/icons.
* **Expressive Emotes:** Players can trigger visual emotes (`💡`, `👍`, `👏`, `👋`) via keys `1`–`4`.

---

## 4. Core Gameplay Loop

### The Central Hub (The Wonder Tree)
The world is defined in `public/world.json` and rendered by `WonderTreeScene.ts`. Players navigate using arrow keys, WASD, or touch/click-to-move on mobile and web.

### Dynamic Minigame Loading
1. The player moves their avatar toward a portal (e.g., *Acorn Scale*, *Rhythm in the Branches*, or *The Clockwork Tower*).
2. `MinigameLoader` checks if the minigame chunk is already loaded in memory.
3. If not, Vite loads the separate JS chunk on-demand and launches the minigame overlay. Completion counts are saved locally via `ProfileManager`.

## 5. Development & Deployment Commands

```bash
# Install dependencies
npm install

# Start local development server
npm run dev

# Run unit tests (Vitest)
npm test

# Build production static web bundle (outputs to dist/)
npm run build

# Sync web bundle with Capacitor for Android / iOS
npm run cap:sync
```
